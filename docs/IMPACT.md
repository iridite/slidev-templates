# Impact and adoption evidence

This project distinguishes **its own adoption** from the popularity of projects it indexes. The registry may include established external projects, but their stars, forks, downloads, users, and reputation are not counted as adoption of `slidev-templates`.

## Public baseline

Baseline date: **2026-09-03**

At the baseline, the repository had:

- 74 GitHub stars and 4 forks;
- a public issue and pull-request workflow;
- an external contributor fix for standalone installation in PR #6;
- an externally reported specification issue triaged through Issue #7;
- four repository-hosted starters and eight upstream-governed registry entries;
- machine-readable registry, schema, gallery, CLI, clean hosted builds, PDF export coverage for Neko Style, and scheduled source/license health checks.

These are early adoption and maintenance signals, not a claim of broad ecosystem adoption.

## Evidence we track

The project treats the following as meaningful evidence:

1. successful use or scaffold reports from people outside the maintainer’s own projects;
2. template submissions and metadata corrections from upstream authors;
3. external pull requests and issues that improve real user workflows;
4. downstream tools, sites, or agents consuming the versioned registry;
5. successful clean builds and compatibility reports across supported runtimes;
6. references or backlinks from canonical upstream template projects;
7. repository stars, forks, clones, traffic, and release/package usage where those measurements are actually available.

## Evidence we do not manufacture

The project does not create fake issues, synthetic contributors, empty releases, mass-generated commits, or misleading download claims. It does not aggregate the popularity of indexed projects into its own metrics. Automated maintenance activity is labeled as automation and remains subject to human review.

## Why the project can matter before broad adoption

Slidev’s public ecosystem contains themes, individual decks, branded starters, multi-talk workspaces, and deployment pipelines, but template-level discovery information is fragmented. A neutral registry can create ecosystem value by making ownership, license evidence, purpose, reproducible start paths, and verification depth comparable through one stable contract.

The project’s next adoption milestone is not a larger README. It is external use of the registry: public gallery traffic, upstream-author participation, reusable registry consumers, and independently confirmed successful scaffolds.
